# 归档会话删除模块

DSH++ 自行提供归档会话删除，官方提供对应能力后可独立移除此模块。代码集中在 `src/modules/archived-sessions/`，主机和浏览器入口各注册一次；LAN 网关不参与会话文件操作。

## 使用和范围

在侧栏显示已归档会话后，打开该行的“…”菜单，选择“永久删除”。确认框先检查目标身份与可删除状态，确认后才提交删除。本机和经过 LAN 网关登录的用户均可使用；仅 `/api/dsh-plusplus/lan` 下的 LAN 配置接口保留本机限制。

首版支持 DSH `0.2.1-rc.2` / `0.2.1-rc.3` 的 JSONL 存储布局和当前 v4 日志，运行平台为 Linux/macOS。文本和 Zstandard 日志均有原生集成测试。其他版本或后端不启用此操作。

删除会清除目标及其所有子代理的全部规范日志 generation、工作区会话记账、归档和置顶记录、投影缓存，并通过原生搜索服务重新核对搜索索引。只沿 `origin: subagent` 与 `parentSession` 的父子关系递归，独立 fork 及其子树、工作区文件、共享附件和其他会话会保留。仅主会话需要归档，子代理无需逐个归档。确认框会显示包含嵌套子代理的总数，单次最多 256 个子代理。

**主会话或任意子代理仍被原生 Session store 或写句柄持有时，整组不能删除。** 归档不会自动释放它们；界面提示重启 DSH 后，在不打开这些会话的情况下重试。仍有任务、定时提醒或其他进程占用时也拒绝。旧格式会话需先由 DSH 正常打开升级、重新归档并释放，再删除；本模块不运行迁移工具。

模块默认启用，可在插件配置中设置 `archivedSessions.enabled: false` 关闭。此配置由原生 Loader 处理，独立于 `lan` 配置。

## 模块边界

| 文件          | 责任                                              |
| ------------- | ------------------------------------------------- |
| `contract.ts` | 功能路径、请求身份、稳定的业务错误                |
| `host.ts`     | 版本/后端识别、原生服务适配、认证后的 HTTP 接口   |
| `manager.ts`  | 归档、活动、血缘、生命周期准入，写锁所有权与重试  |
| `files.ts`    | 限定版本的 JSONL 布局适配、日志移除、持久删除凭据 |
| `client.ts`   | 原生菜单 Slot、确认框、会话列表刷新及资源释放     |

原生版本尚无永久删除 API。本模块通过公共服务获取当前持久化配置、会话状态和写句柄；缺失的文件删除操作由插件自己的布局适配器完成。不会修改官方安装文件、替换服务方法、伪造 `session/disposed` 事件或读取私有运行时字段。投影缓存通过公开 Domain 表句柄删除，搜索索引通过原生搜索服务的正常 reconciliation 清理。原生默认 web 配置 `openAt: never` 会明确返回 `SESSION_QUERY_SEARCH_DISABLED`，此时没有启用的索引需要核对；仅忽略此错误，其他清理错误仍需重试。缓存及索引检查在移除侧栏记录之前完成。

布局适配器的版本门槛与归属校验是删除前提。更新支持版本时，需重新验证原生文件布局、写锁、空闲写句柄关闭、缓存及工作区接口；不能仅放宽版本范围。

## 删除流程与恢复

1. 请求只携带 `sessionId`、确认时的 `createdAt` 和 `treeRevision`，不接受目录、文件路径或删除通配符。树版本绑定主会话及全部子代理的身份和血缘，列表发生变化需要重新检查并确认。
2. Host 检查主会话归档状态、全部成员的内存持有、日志格式、子代理血缘和原生活动准入。异步活动检查后再次核对树。
3. 通过 `sessionPersistence.open(id, 'write')` 取得所有成员的原生排他写句柄，再开始任何日志删除。它同时排除本进程和其他进程的写入；插件不窃取其他 owner 的 disposer。
4. 持锁后重新检查身份、血缘和活动。检查所有成员的每级目录及日志文件，拒绝符号链接、硬链接、未知文件和不支持的 generation；任意成员未通过时不删除任何日志。
5. 先持久化主会话上的整组删除清单，再持久化每个成员的删除凭据，然后同步从叶子到主会话删除日志。每个成员先删除旧 generation，最后删除当前 generation，并同步目录。删除前再次同步检查归档和生命周期状态。
6. 持锁清理原生缓存、搜索索引、工作区、归档及置顶记录，子代理先于主会话；全部完成才报告成功。退出路径总会关闭全部句柄，卸载会中止尚未提交的工作并等待正在处理的请求。

每个已删除会话目录保留 `session.lock` 与 `.dsh-plusplus-delete.json`。锁文件的 inode 必须保留，才能维持原生跨进程互斥。删除凭据只记录会话身份、目录归属、规范文件名及完成状态，主会话凭据还记录确认过的子代理身份与父子关系，不含聊天内容或认证凭据。永久删除指日志和相应可用记录的逻辑删除，不是磁盘安全擦除或对备份的清除。

请求超时或清理失败不会被报告为成功。重试使用同一会话身份和整组清单，凭据证明之前已开始的操作；普通“文件不存在”不能冒充删除成功。启动时仅恢复整组日志已全部移除的元数据清理，不会自动开始新的日志删除。中途只移除部分 generation 或部分子代理的操作保留主会话记录，等待用户明确重试，不能单独恢复组内成员。身份被重新创建、子树发生变化或布局不符合预期时拒绝继续。

进程外已打开的只读观察可以继续持有旧内存快照，独立 fork 也保留已复制的历史。此功能不清除别的进程内存、外部备份或共享附件。

## 网络和 UI

接口为 `/api/dsh-plusplus/archived-sessions`。GET 返回能力和变更版本；POST 的 `preview` 只检查，`delete` 执行确认过的身份。所有请求要求原生认证，POST 要求完整同源 Origin 和有界 JSON 请求体。LAN 网关先验证自己的会话及外部 Origin，再按照现有逻辑代理原生认证；匿名请求不会到达功能接口。

删除按钮通过 `sidebar.workspaces.session.menu.item` 注册，确认框通过 `shell.overlay` 注册。仅已归档行显示操作；渲染菜单不会激活或 retain 会话。确认框默认聚焦取消，提交时防止重复操作，失败后保留原身份以便重试。完成后刷新原生列表；其他打开的客户端通过功能版本轮询刷新。模块卸载释放 Slot、定时器、请求和订阅。

## 验证

`npm run check` 包含模块测试和扩展后的原生插件验证。测试仅使用临时 profile、日志和 loopback listener，不运行模型、不修改用户数据。

覆盖文本/压缩日志、历史 generation 清除、整组跨实例写锁、归档与活动拒绝、嵌套子代理级联、独立 fork 保留、确认后子树变化、身份重建、符号链接和未知文件、部分删除重试、整组重启恢复、卸载、取消确认、重复提交，以及经过 LAN 的成功删除、搜索启用/关闭、匿名/跨源拒绝与 LAN 配置隔离。

移除此模块时，删除模块目录及对应主机/浏览器注册、配置与专属依赖/测试即可。保留的删除凭据和锁文件没有聊天内容，原生会话列表不会把它们当成日志；不需要复原任何官方代码补丁。
